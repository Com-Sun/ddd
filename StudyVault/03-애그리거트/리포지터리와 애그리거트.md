## 리포지터리는 애그리거트 단위로 존재한다

> [!important]
> 애그리거트는 **개념상 완전한 한 개의 도메인 모델**을 표현하므로,
> 객체의 영속성을 처리하는 리포지터리는 **애그리거트 단위로 존재**한다.

`Order`와 `OrderLine`을 물리적으로 각각 **별도의 DB 테이블에 저장한다고 해서** `Order`와 `OrderLine`을 위한 리포지터리를 **각각 만들지 않는다.**
`Order`가 애그리거트 루트고 `OrderLine`은 애그리거트에 속하는 구성요소이므로, **`Order`를 위한 리포지터리만 존재**한다.

```
   [ 물리 저장소 ]              [ 리포지터리 ]
   ORDERS 테이블      ┐
   ORDER_LINE 테이블  ├──▶   OrderRepository  (오직 하나)
   ORDERER 테이블     ┘
                              ❌ OrderLineRepository (만들지 않는다)
```

## 기본 두 메서드

| 메서드 | 역할 |
|--------|------|
| `save` | **애그리거트 저장** |
| `findById` | **ID로 애그리거트를 구함** |

이 두 메서드 외에 필요에 따라 **다양한 조건으로 애그리거트를 검색하는 메서드**나 **삭제 메서드**를 추가할 수 있다.

## 저장 — 애그리거트 전체를 영속화

> [!important]
> 애그리거트는 개념적으로 하나이므로 리포지터리는 **애그리거트 전체를 저장소에 영속화**해야 한다.

```java
// 리포지터리에 애그리거트를 저장하면 애그리거트 전체를 영속화해야 한다.
orderRepository.save(order);
```

`Order` 애그리거트와 관련된 테이블이 **세 개**라면, `Order` 애그리거트를 저장할 때
**애그리거트 루트와 매핑되는 테이블뿐만 아니라 애그리거트에 속한 모든 구성요소에 매핑된 테이블에 데이터를 저장**해야 한다.

## 조회 — 완전한 애그리거트를 제공

```java
// 리포지터리는 완전한 Order를 제공해야 한다.
Order order = orderRepository.findById(orderId);

// Order가 온전한 애그리거트가 아니면
// 기능 실행 도중 NullPointerException과 같은 문제가 발생한다.
order.cancel();
```

> [!danger]
> 리포지터리가 완전한 애그리거트를 제공하지 않으면 필드나 값이 올바르지 않아
> 애그리거트의 기능을 실행하는 도중에 **`NullPointerException`과 같은 문제가 발생**할 수 있다.

## 원자성 — 모든 변경을 원자적으로

> [!important]
> 저장소로 **MariaDB·오라클 같은 RDBMS뿐만 아니라 몽고DB 같은 NoSQL**도 함께 사용하는 곳이 증가하고 있다.
> **무엇을 사용하든 애그리거트의 상태가 변경되면 모든 변경을 원자적으로 저장소에 반영해야 한다.**
>
> 애그리거트에서 **두 개의 객체를 변경했는데 저장소에는 한 객체에 대한 변경만 반영되면 데이터 일관성이 깨진다.**

| 저장소 | 원자성 보장 방법 |
|--------|------------------|
| **RDBMS** | **트랜잭션**을 이용해서 애그리거트의 변경이 저장소에 반영되는 것을 보장 |
| **몽고DB** | 한 애그리거트를 **한 개 문서(document)에 저장**함으로써 변경을 손실 없이 반영 |

## ★ 구현 기술이 애그리거트 구현에 영향을 준다

> [!warning] 역방향 영향
> **어떤 기술을 이용해서 리포지터리를 구현하느냐에 따라 애그리거트의 구현도 영향을 받는다.**

| 상황 | 영향 |
|------|------|
| JPA 사용 시 | 데이터베이스 **관계형 모델에 객체 도메인 모델을 맞춰야 할 때**가 있다 |
| 레거시 DB 사용 / 팀 내 DB 설계 표준 준수 | **DB 테이블 구조에 맞게 모델을 변경**해야 한다 |
| 그 결과 | 밸류 타입인 도메인 모델을 `@Embeddable`(밸류 매핑용)이 아닌 **`@Entity`(엔티티 매핑용)로 매핑해야 할 수도** 있다 |

| Scenario/Keyword | Answer |
|-------------------|--------|
| "리포지터리는 무슨 단위로 존재?" | **애그리거트 단위** |
| "`OrderLineRepository`를 만들어야 하나?" | **아니다.** `OrderRepository`만 존재 |
