## ① ★ 예제 프로젝트 자체의 문제 (학습 시 주의)

> [!danger] 이 두 가지는 **노트가 아니라 예제 코드의 문제**다. 노트는 책 기준이 맞다.

### 🔴 문제 1 — `StartShippingService`의 버전 검사 로직이 반대

**실제 코드** (`ddd-start2/src/main/java/com/myshop/order/command/application/StartShippingService.java`)

```java
@Transactional
public void startShipping(StartShippingRequest req) {
    Optional<Order> orderOpt = orderRepository.findById(new OrderNo(req.getOrderNumber()));
    Order order = orderOpt.orElseThrow(() -> new NoOrderException());
    if (order.matchVersion(req.getVersion())) {     // ❌ ! 가 없다
        throw new VersionConflictException();
    }
    order.startShipping();
}
```

**책 p.260 원문**

```java
if (!order.matchVersion(req.getVersion())) {        // ⭕ ! 있음
    throw new VersionConflictException();
}
order.startShipping();
```

> [!danger] 무엇이 잘못됐나
> `matchVersion()`은 **버전이 일치하면 `true`** 를 리턴한다(책 p.260 명시).
> 따라서 **`!`가 빠지면 로직이 정확히 반대**가 된다.
>
> | 상황 | 책의 동작 | 실제 코드의 동작 |
> |------|-----------|------------------|
> | 버전 **일치** (정상) | 배송 시작 ⭕ | **예외 발생** ❌ |
> | 버전 **불일치** (충돌) | 예외 발생 ⭕ | **그대로 배송 시작** ❌ |
>
> 즉 **정상 요청은 거부되고, 실제 충돌은 통과**한다.
> [[비선점 잠금]] 노트는 **책 기준(`!` 포함)이 맞으므로 수정하지 않았다.**

**직접 고쳐보기**: `!`를 추가하면 된다. → [[코드 리딩 연습문제]] Q9

### 🟡 문제 2 — `EventForwarder`가 실행되지 않는다

`integration/EventForwarder.java`에 `@Scheduled(initialDelay = 1000L, fixedDelay = 1000L)`가 붙어 있지만,
**프로젝트 전체에 `@EnableScheduling`이 없다.**

```bash
grep -rn "EnableScheduling" ddd-start2/src/     # 결과 없음
```

`ShopApplication.java`에 있는 것은 `@EnableAsync`, `@EnableJpaRepositories`뿐이다.

> [!warning]
> 스프링은 **`@EnableScheduling` 없이는 `@Scheduled`를 처리하지 않는다.**
> 따라서 **포워더는 절대 실행되지 않으며**, 10.5.3 [[이벤트 저장소를 이용한 비동기 처리]]의 포워더 방식을 눈으로 확인할 수 없다.
>
> **의도적일 수 있다** — `SysoutEventSender`가 1초마다 콘솔에 출력하면 로그가 지저분해진다.
> **직접 보려면** `ShopApplication`에 `@EnableScheduling`을 추가한다. → [[코드 리딩 연습문제]] Q10
>
> 참고로 **API 방식**(`GET /api/events?offset=0&limit=5`)은 정상 동작한다.

## ④ 책보다 실제 코드가 더 나아간 부분

> 책에는 없거나 간략했지만 실제 코드에 **더 완성된 형태**로 존재하는 것들이다.

| 항목 | 실제 코드 | 관련 노트 |
|------|-----------|-----------|
| **식별자 생성을 리포지터리 `default` 메서드로** | `OrderRepository.nextOrderNo()` — 인터페이스 안에서 바로 구현 | [[식별자 생성 기능]] |
| **COUNT 회피 커스텀 리포지터리 실물** | `common/jpa/Rangeable*.java` 3개 + `@EnableJpaRepositories(repositoryBaseClass=…)` | [[페이징 처리하기]] |
