# 동기 이벤트 처리 문제 (★★★)

#ddd #event #transaction #concept

## Overview Table (한눈에 비교)

| 항목 | 핵심 내용 |
|------|-----------|
| 해결된 것 | 이벤트로 **강결합 문제는 해소**했다 |
| **남은 문제** | **외부 서비스에 영향을 받는 문제** |
| 문제 ① | **성능** — 외부 서비스가 느려지면 내 기능도 느려진다 |
| 문제 ② | **트랜잭션** — 외부 실행 실패 시 롤백해야 하는가? |
| 해법 | **이벤트를 비동기로 처리**하거나 **이벤트와 트랜잭션을 연계** |

## 문제 코드

```java
// 1. 응용 서비스 코드
@Transactional     // 외부 연동 과정에서 익셉션이 발생하면 트랜잭션 처리는?
public void cancel(OrderNo orderNo) {
    Order order = findOrder(orderNo);
    order.cancel();     // order.cancel()에서 OrderCanceledEvent 발생
}
```

```java
// 2. 이벤트를 처리하는 코드
@Service
public class OrderCanceledEventHandler {

    @EventListener(OrderCanceledEvent.class)
    public void handle(OrderCanceledEvent event) {
        // refundService.refund()가 느려지거나 익셉션이 발생하면?
        refundService.refund(event.getOrderNumber());
    }
}
```

> [!important] 왜 아직 문제인가
> **이벤트를 사용해서 강결합 문제는 해소했지만 아직 남아 있는 문제가 하나 있다.
> 바로 외부 서비스에 영향을 받는 문제다.**
>
> 스프링의 기본 `@EventListener`는 **동기(synchronous)** 로 동작한다.
> 즉 `Events.raise()` → 핸들러 실행이 **같은 스레드, 같은 트랜잭션**에서 이루어진다.

```
   cancel()  [트랜잭션 시작]
      │
   order.cancel() → Events.raise()
      │
      └──▶ handle() → refundService.refund() ──▶ 외부 결제 시스템
                                                      │
      ◀──────────── 느려지면 그대로 대기 ◀────────────┘
      │
   [트랜잭션 커밋]
```

## 문제 ① — 성능

> [!warning]
> `refundService.refund()`가 외부 환불 서비스와 연동한다고 가정하면,
> **만약 외부 환불 기능이 갑자기 느려지면 `cancel()` 메서드도 함께 느려진다.**
> 이것은 **외부 서비스의 성능 저하가 바로 내 시스템의 성능 저하로 연결된다**는 것을 의미한다.

## 문제 ② — 트랜잭션

> [!danger]
> **성능 저하뿐만 아니라 트랜잭션도 문제가 된다.**
> `refundService.refund()`에서 **익셉션이 발생하면 `cancel()` 메서드의 트랜잭션을 롤백 해야 할까?**
> 트랜잭션을 롤백 하면 **구매 취소 자체를 롤백 하는 것**이므로 **구매 취소가 실패하는 것과 같다.**

> [!important] 생각해 볼 점
> **외부 환불 서비스 실행에 실패했다고 해서 반드시 트랜잭션을 롤백 해야 하는지**에 대한 문제다.
> **일단 구매 취소 자체는 처리하고 환불만 재처리하거나 수동으로 처리할 수도 있다.**

```
   외부 환불 실패
        ├─ 롤백  → 구매 취소도 실패  ❌ (사용자 입장에서 부당)
        └─ 커밋  → 구매는 취소, 환불은 나중에 재시도  ⭕
```

## 해법 방향

> [!important]
> **외부 시스템과의 연동을 동기로 처리할 때 발생하는 성능과 트랜잭션 범위 문제를 해소하는 방법은
> 이벤트를 비동기로 처리하거나 이벤트와 트랜잭션을 연계하는 것**이다.
