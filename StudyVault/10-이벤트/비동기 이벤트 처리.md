## ★ 핵심 통찰

> [!important] (p.319)
> **우리가 구현해야 할 것 중에서 "A 하면 이어서 B 하라"는 내용을 담고 있는 요구사항은
> 실제로 "A 하면 최대 언제까지 B 하라"인 경우가 많다.**
> 즉 **일정 시간 안에만 후속 조치를 처리하면 되는 경우가 적지 않다.**
>
> 게다가 **B를 하는 데 실패하면 일정 간격으로 재시도를 하거나 수동 처리를 해도 상관없는 경우**가 있다.

**예시**

| 요구사항 | 실제 요구 |
|----------|-----------|
| 회원 가입 신청을 하면 **검증 이메일을 보낸다** | 바로 도착할 필요 없다. **10~20초 후에 도착해도 되고**, 못 받으면 **재전송 요청**을 쓰면 된다 |
| 주문을 취소하면 **결제를 취소한다** | **수십 초 내에** 이루어지면 된다. **며칠 뒤에 확실하게 취소되면 문제없을 때**도 있다 |

> [!tip] 이벤트로의 번역
> **"A 하면"** 은 **이벤트**로 볼 수 있다.
> "회원 가입 신청을 하면 인증 이메일을 보내라" → **'회원 가입 신청함 이벤트'** 를 처리하는 **핸들러에서 이메일을 보낸다.**

```
   "A 하면 이어서 B 하라"
            ▼
   "A 하면 최대 언제까지 B 하라"로 바꿀 수 있는가?
            ▼ 예
   A 이벤트 발생 → 별도 스레드로 B를 수행하는 핸들러 실행
```

## §10.5.1 로컬 핸들러 비동기 실행

> 이벤트 핸들러를 **별도 스레드로 실행**하는 방식이다. 스프링에서는 두 단계면 된다.

### 1단계 — `@EnableAsync`로 비동기 기능 활성화

```java
@SpringBootApplication
@EnableAsync
public class ShopApplication {

    public static void main(String[] args) {
        SpringApplication.run(ShopApplication.class, args);
    }
}
```

> `@EnableAsync` 애너테이션은 **스프링의 비동기 실행 기능을 활성화**한다.
> 스프링 부트를 사용한다면 **`@SpringBootApplication` 애너테이션을 붙인 클래스에 함께 붙이면 된다.**

### 2단계 — 핸들러 메서드에 `@Async`

```java
import org.springframework.scheduling.annotation.Async;

@Service
public class OrderCanceledEventHandler {

    @Async
    @EventListener(OrderCanceledEvent.class)
    public void handle(OrderCanceledEvent event) {
        refundService.refund(event.getOrderNumber());
    }
}
```

> [!important]
> 스프링은 **`OrderCanceledEvent`가 발생하면 `handle()` 메서드를 별도 스레드를 이용해서 비동기로 실행**한다.

```
   cancel()  [트랜잭션]
      │
   Events.raise(OrderCanceledEvent)
      │
      ├──▶ 즉시 리턴 → 트랜잭션 커밋 → 응답     ⭕ 빠르다
      │
      └──▶ [별도 스레드] handle() → refundService.refund()
```

| 장점 | 단점 |
|------|------|
| **구현이 가장 간단** (애너테이션 2개) | 애플리케이션이 **죽으면 이벤트가 유실**된다 |
| 외부 서비스 성능이 **내 시스템에 영향을 주지 않는다** | 실패 시 **재처리 보장이 없다** |

> [!note] 이벤트 유실 문제
> 로컬 핸들러를 이용해 이벤트를 비동기로 처리할 경우 **이벤트 처리에 실패하면 이벤트를 유실**하게 된다.
> → 이를 보완하는 것이 [[이벤트 저장소를 이용한 비동기 처리]]다.

## Exam/Test Patterns (시험 빈출 패턴)

| Scenario/Keyword | Answer |
|-------------------|--------|
| "'A 하면 이어서 B 하라'의 실제 의미" | **'A 하면 최대 언제까지 B 하라'** |
| "B가 실패하면?" | **재시도하거나 수동 처리해도 되는 경우가 있다** |
| "비동기 구현 방식 네 가지" | **로컬 핸들러 / 메시지 큐 / 이벤트 저장소+포워더 / 이벤트 저장소+API** |
| "비동기 활성화 애너테이션" | **`@EnableAsync`** |
| "핸들러를 비동기로 만드는 애너테이션" | **`@Async`** |
| "붙이는 위치" | `@EnableAsync`는 **`@SpringBootApplication` 클래스**, `@Async`는 **핸들러 메서드** |
| "로컬 핸들러 비동기의 약점" | **이벤트 유실** (처리 실패 시) |
