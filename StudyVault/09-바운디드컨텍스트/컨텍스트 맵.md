# 컨텍스트 맵 (★★★)

#ddd #bounded-context #context-map #concept

## Overview Table (한눈에 비교)

| 항목 | 핵심 내용 |
|------|-----------|
| 문제 | 개별 바운디드 컨텍스트에 매몰되면 **전체를 보지 못한다** ("나무만 보고 숲을 못 본다") |
| 정의 | **바운디드 컨텍스트 간의 관계를 표시한 지도** |
| 표기 | **정해진 규칙이 없다.** 간단한 도형과 선으로 관계를 이해할 수 있는 수준이면 된다 |
| 흔한 표기 | **OHS**(공개 호스트 서비스), **ACL**(안티코럽션 계층) |
| 추가로 표시하면 좋은 것 | **주요 애그리거트**, **하위 도메인**, **조직 구조** |
| 도구 | **화이트보드, 파워포인트** 등 (단순해서 쉽게 그릴 수 있다) |
| ★ 성질 | **시스템의 전체 이해 수준을 보여준다** → 이해가 깊어지면 **맵도 함께 바뀐다** |

## 왜 필요한가

> [!important]
> **개별 바운디드 컨텍스트에 매몰되면 전체를 보지 못할 때가 있다.**
> **나무만 보고 숲을 보지 못하는 상황을 피하려면 전체를 조망할 수 있는 지도가 필요**한데,
> 그것이 바로 **컨텍스트 맵**이다.

## 컨텍스트 맵 예

```
   ┌──────────────────┐         ┌──────────────────┐
   │ 카탈로그          │  ACL    │ 추천              │
   │ (Product,        │ ──▶◇──▶ │ (RecItem)        │
   │  Category)       │         │      OHS         │
   └──────────────────┘         └──────────────────┘
           │                              ▲
           │ ACL                          │ OHS
           ▼                              │
   ┌──────────────────┐         ┌──────────────────┐
   │ 주문              │         │ 검색              │
   │ (Order, Orderer) │ ──────▶ │ (Document)       │
   └──────────────────┘         └──────────────────┘

   OHS = Open Host Service (공개 호스트 서비스)
   ACL = Anticorruption Layer (안티코럽션 계층)
```

> [!tip] 이 그림만 봐도
> - 각 **바운디드 컨텍스트의 경계가 명확하게 드러나고**
> - 서로 **어떤 관계를 맺고 있는지** 알 수 있다
> - 바운디드 컨텍스트 영역에 **주요 애그리거트를 함께 표시하면 모델에 대한 관계가 더 명확히 드러난다**
> - **하위 도메인이나 조직 구조를 함께 표시**하면 도메인을 포함한 전체 관계를 이해하는 데 도움이 된다

## 컨텍스트 맵이 주는 것

> [!important] (p.298)
> **컨텍스트 맵은 시스템의 전체 구조를 보여준다.**
> 이는:
> - **하위 도메인과 일치하지 않는 바운디드 컨텍스트를 찾아**
> - **도메인에 맞게 바운디드 컨텍스트를 조절**하고
> - 사업의 **핵심 도메인을 위해 조직 역량을 어떤 바운디드 컨텍스트에 집중할지 파악**하는 데 도움을 준다

```
   컨텍스트 맵
        ├─▶ 하위 도메인과 어긋난 컨텍스트 발견 → 경계 조절
        └─▶ 핵심 도메인 식별 → 조직 역량 집중 대상 결정
```

## 그리는 방법

> [!tip] 규칙은 없다
> **컨텍스트 맵을 그리는 규칙은 따로 없다.**
> **간단한 도형과 선을 이용해서 각 컨텍스트의 관계를 이해할 수 있는 수준에서 그리면 된다.**
> 컨텍스트 맵은 단순하기 때문에 **화이트보드나 파워포인트 같은 도구를 이용해서 쉽게 그릴 수 있다.**

## ★ 컨텍스트 맵은 살아 있는 문서다

> [!important]
> **컨텍스트 맵은 전체 시스템의 이해 수준을 보여준다.**
> 즉 **시스템을 더 잘 이해하거나 시간이 지나면서 컨텍스트 간 관계가 바뀌면 컨텍스트 맵도 함께 바뀐다.**

```
   시스템 이해 ↑  또는  컨텍스트 관계 변화
              ▼
        컨텍스트 맵 갱신
```

> [!note] 유비쿼터스 언어와 같은 성질
> 1장 [[도메인 용어와 유비쿼터스 언어]]에서 "**새로 발견한 용어는 코드나 문서에도 반영해서 산출물에 최신 모델을 적용한다**"고 했다.
> 컨텍스트 맵도 **이해가 깊어질수록 갱신되는 산출물**이라는 점에서 같다.

## Exam/Test Patterns (시험 빈출 패턴)

| Scenario/Keyword | Answer |
|-------------------|--------|
| "나무만 보고 숲을 못 볼 때 필요한 것" | **컨텍스트 맵** |
| "컨텍스트 맵이란" | **바운디드 컨텍스트 간의 관계를 표시한 지도** |
| "OHS / ACL" | **공개 호스트 서비스 / 안티코럽션 계층** |
| "함께 표시하면 좋은 것" | **주요 애그리거트, 하위 도메인, 조직 구조** |
| "그리는 규칙" | **정해진 규칙 없음** — 이해할 수 있는 수준이면 된다 |
| "컨텍스트 맵으로 알 수 있는 것" | 하위 도메인과 **어긋난 컨텍스트 발견**, **조직 역량 집중 대상** 파악 |
| "언제 바뀌는가" | 시스템 **이해가 깊어지거나 관계가 바뀔 때** |
