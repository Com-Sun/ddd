# 스펙 조합 (★★★)

#ddd #query #specification #concept

## Overview Table (네 가지 메서드)

| 메서드 | 종류 | 역할 |
|--------|------|------|
| **`and()`** | 디폴트 메서드 | 두 스펙을 **모두 충족**하는 조건 |
| **`or()`** | 디폴트 메서드 | 두 스펙 중 **하나 이상 충족**하는 조건 |
| **`not()`** | **정적** 메서드 | 조건을 **반대로** 적용 |
| **`where()`** | **정적** 메서드 | **`null`이면 아무 조건도 만들지 않고**, 아니면 그대로 리턴 |

## `and()` / `or()` (리스트 5.5)

```java
public interface Specification<T> extends Serializable {
    ...생략

    default Specification<T> and(@Nullable Specification<T> other) { ... }
    default Specification<T> or(@Nullable Specification<T> other) { ... }

    @Nullable
    Predicate toPredicate(Root<T> root,
                          CriteriaQuery<?> query,
                          CriteriaBuilder criteriaBuilder);
}
```

> [!important]
> `and()`와 `or()`는 **스펙 인터페이스에 정의된 디폴트 메서드**다.
> - `and()`: 두 스펙을 **모두 충족**하는 조건을 표현하는 스펙 생성
> - `or()`: 두 스펙 중 **하나 이상 충족**하는 조건을 표현하는 스펙 생성

```java
Specification<OrderSummary> spec1 = OrderSummarySpecs.ordererId("user1");
Specification<OrderSummary> spec2 = OrderSummarySpecs.orderDateBetween(
        LocalDateTime.of(2022, 1, 1, 0, 0, 0),
        LocalDateTime.of(2022, 1, 2, 0, 0, 0));
Specification<OrderSummary> spec3 = spec1.and(spec2);
```

### 변수 없이 체이닝

> 개별 스펙 조건마다 변수를 선언하지 않아도 된다. **바로 `and()`를 사용하면 불필요한 변수 사용을 줄일 수 있다.**

```java
Specification<OrderSummary> spec =
        OrderSummarySpecs.ordererId("user1")
                .and(OrderSummarySpecs.orderDateBetween(from, to));
```

## `not()` — 정적 메서드

```java
Specification<OrderSummary> spec =
        Specification.not(OrderSummarySpecs.ordererId("user1"));
```

> **`not()`은 정적 메서드로 조건을 반대로 적용할 때 사용한다.**

## ★ `where()` — null 안전 조합

> [!warning] 문제 — 매번 null 검사는 귀찮다
> `null` 가능성이 있는 스펙 객체와 다른 스펙을 조합해야 할 때가 있다.
> 이 경우 `null` 여부를 판단해서 **`NullPointerException`이 발생하는 것을 방지**해야 하는데, 매번 검사하려면 다소 귀찮다.

```java
Specification<OrderSummary> nullableSpec = createNullableSpec();  // null일 수 있음
Specification<OrderSummary> otherSpec = createOtherSpec();

Specification<OrderSummary> spec =
        nullableSpec == null ? otherSpec : nullableSpec.and(otherSpec);
```

### ⭕ `where()`로 간단하게

> [!important]
> **`where()`는 스펙 인터페이스의 정적 메서드로,**
> **`null`을 전달하면 아무 조건도 생성하지 않는 스펙 객체를 리턴**하고,
> **`null`이 아니면 인자로 받은 스펙 객체를 그대로 리턴**한다.

```java
Specification<OrderSummary> spec =
        Specification.where(createNullableSpec()).and(createOtherSpec());
```

```
   Specification.where(null)      →  "아무 조건 없음" 스펙  (NPE 방지)
   Specification.where(spec)      →  spec 그대로
```

## 정리

```
   spec1.and(spec2)                 →  spec1 AND spec2
   spec1.or(spec2)                  →  spec1 OR  spec2
   Specification.not(spec1)         →  NOT spec1
   Specification.where(nullable)    →  null-safe 시작점
        .and(...)                       ← 이어서 조합
```

## Exam/Test Patterns (시험 빈출 패턴)

| Scenario/Keyword | Answer |
|-------------------|--------|
| "두 스펙을 모두 충족" | **`and()`** (디폴트 메서드) |
| "두 스펙 중 하나 이상" | **`or()`** (디폴트 메서드) |
| "조건을 반대로" | **`not()`** (정적 메서드) |
| "`and`/`or`는 무슨 메서드?" | **디폴트 메서드** |
| "`not`/`where`는 무슨 메서드?" | **정적 메서드** |
| "`null` 스펙과 조합 시 NPE 방지" | **`Specification.where()`** |
| "`where(null)`의 결과" | **아무 조건도 생성하지 않는 스펙** |
