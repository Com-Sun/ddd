# 동적 인스턴스를 이용한 조회 (★★★)

#ddd #query #dynamic-instance #concept

## Overview Table (한눈에 비교)

| 항목 | 핵심 내용 |
|------|-----------|
| 기능 | JPA는 **쿼리 결과에서 임의의 객체를 동적으로 생성**할 수 있다 |
| 문법 | JPQL `select` 절의 **`new` 키워드** + **완전한 클래스 이름** + 생성자 인자 |
| ★ 장점 ① | **JPQL을 그대로 사용**하므로 객체 기준으로 쿼리 작성 |
| ★ 장점 ② | **지연/즉시 로딩 같은 고민 없이** 원하는 모습으로 데이터 조회 |
| 부가 팁 | 표현 영역이 다루기 쉽도록 **기본 타입으로 변환**해두면 편리 |

## JPQL `new` 키워드 (리스트 5.7)

```java
public interface OrderSummaryDao
        extends Repository<OrderSummary, String> {

    @Query("""
        select new com.myshop.order.query.dto.OrderView(
            o.number, o.state, m.name, m.id, p.name
        )
        from Order o join o.orderLines ol, Member m, Product p
        where o.orderer.memberId.id = :ordererId
        and o.orderer.memberId.id = m.id
        and index(ol) = 0
        and ol.productId.id = p.id
        order by o.number.number desc
        """)
    List<OrderView> findOrderView(String ordererId);
}
```

> [!important] 문법
> JPQL의 `select` 절에 **`new` 키워드**가 있다.
> `new` 키워드 뒤에 **생성할 인스턴스의 완전한 클래스 이름**을 지정하고,
> **괄호 안에 생성자에 인자로 전달할 값**을 지정한다.

```
   select new com.myshop.order.query.dto.OrderView(
              └──────── 완전한 클래스 이름 ────────┘
       o.number, o.state, m.name, m.id, p.name
       └────────── 생성자 인자 ──────────┘
   )
```

## 대상 클래스

```java
public class OrderView {
    private final String number;
    private final OrderState state;
    private final String memberName;
    private final String memberId;
    private final String productName;

    public OrderView(OrderNo number, OrderState state,
                     String memberName, MemberId memberId,
                     String productName) {
        this.number = number.getNumber();
        this.state = state;
        this.memberName = memberName;
        this.memberId = memberId.getId();
        this.productName = productName;
    }

    ... // get 메서드
}
```

> [!tip] 기본 타입으로 변환해두는 이유 (p.194)
> **조회 전용 모델을 만드는 이유는 표현 영역을 통해 사용자에게 데이터를 보여주기 위함**이다.
> 많은 웹 프레임워크는 **`Money` 같은 밸류 타입을 알맞은 형식으로 출력하지 못하므로**,
> 위 코드처럼 **값을 기본 타입으로 변환하면 편리**하다.
>
> 물론 사용하는 웹 프레임워크에 익숙하다면 `Money`를 원하는 형식으로 출력하도록 **프레임워크를 확장**해서
> 조회 전용 모델에서 기본 타입으로 변환하지 않아도 된다.

## ★ 동적 인스턴스의 장점

> [!important]
> 동적 인스턴스의 장점은 **JPQL을 그대로 사용하므로 객체 기준으로 쿼리를 작성하면서도,
> 동시에 지연/즉시 로딩과 같은 고민 없이 원하는 모습으로 데이터를 조회할 수 있다**는 점이다.

```
   [ 애그리거트 로딩 ]                [ 동적 인스턴스 ]
   findById(id)                        select new OrderView(...)
        ▼                                     ▼
   지연/즉시 로딩 전략 고민 필요        로딩 전략 고민 불필요
   불필요한 데이터까지 로딩             필요한 데이터만 정확히 조회
   카타시안 조인 위험                   한 번의 쿼리
```

## Exam/Test Patterns (시험 빈출 패턴)

| Scenario/Keyword | Answer |
|-------------------|--------|
| "쿼리 결과로 임의의 객체 생성" | **동적 인스턴스** |
| "사용하는 JPQL 키워드" | **`new`** |
| "`new` 뒤에 지정하는 것" | **완전한 클래스 이름** |
| "괄호 안에 지정하는 것" | **생성자 인자** |
| "동적 인스턴스의 두 장점" | **JPQL 그대로 사용** + **로딩 전략 고민 불필요** |
| "조회 전용 모델에서 기본 타입 변환 이유" | 웹 프레임워크가 **밸류 타입을 출력하지 못함** |
