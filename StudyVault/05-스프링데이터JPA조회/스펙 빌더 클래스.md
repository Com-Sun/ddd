# 스펙 조합을 위한 스펙 빌더 클래스 (★★)

#ddd #query #specification #concept

## Overview Table (한눈에 비교)

| 항목 | 핵심 내용 |
|------|-----------|
| 문제 | 조건에 따라 스펙을 조합할 때 **`if` 블록 + 변수 재할당**이 반복된다 |
| 해법 | **스펙 빌더 클래스** (메서드 체이닝) |
| 제공 메서드 | **`ifTrue()`, `ifHasText()`, `and()`** (+ 필요한 메서드 추가) |
| 효과 | 코드 양은 비슷하지만 **가독성 ↑, 구조 단순화**, 연속된 변수 할당 제거 |

## 문제 — if 블록과 변수 재할당

```java
Specification<MemberData> spec = Specification.where(null);

if (searchRequest.isOnlyNotBlocked()) {
    spec = spec.and(MemberDataSpecs.nonBlocked());
}
if (StringUtils.hasText(searchRequest.getName())) {
    spec = spec.and(MemberDataSpecs.nameLike(searchRequest.getName()));
}

List<MemberData> results =
        memberDataDao.findAll(spec, PageRequest.of(0, 5));
```

> [!warning]
> **조건에 따라 스펙을 조합해야 할 때** `if` 블록과 `spec = spec.and(...)` 재할당이 반복된다.

## ⭕ 스펙 빌더 사용

```java
Specification<MemberData> spec = SpecBuilder.builder(MemberData.class)
        .ifTrue(searchRequest.isOnlyNotBlocked(),
                () -> MemberDataSpecs.nonBlocked())
        .ifHasText(searchRequest.getName(),
                name -> MemberDataSpecs.nameLike(searchRequest.getName()))
        .toSpec();

List<MemberData> result =
        memberDataDao.findAll(spec, PageRequest.of(0, 5));
```

> [!important] 효과 (p.190)
> `if` 블록을 사용할 때와 비교하면 **코드 양은 비슷한데**,
> **메서드를 사용해서 조건을 표현하고 메서드 호출 체인으로 연속된 변수 할당을 줄여
> 코드 가독성을 높이고 구조가 단순해졌다.**

```
   [ if 블록 ]                      [ 스펙 빌더 ]
   spec = Specification.where(null)  SpecBuilder.builder(X.class)
   if (조건1) spec = spec.and(A)       .ifTrue(조건1, () -> A)
   if (조건2) spec = spec.and(B)       .ifHasText(값, v -> B)
                                        .toSpec()
   ▲ 재할당 반복                       ▲ 체이닝, 재할당 없음
```

## 스펙 빌더 구조 (리스트 5.6)

```java
import org.springframework.data.jpa.domain.Specification;
import org.springframework.util.StringUtils;

import java.util.ArrayList;
import java.util.List;
import java.util.function.Function;
import java.util.function.Supplier;

public class SpecBuilder {

    public static <T> Builder<T> builder(Class<T> type) {
        return new Builder<T>();
    }

    public static class Builder<T> {
        private List<Specification<T>> specs = new ArrayList<>();

        public Builder<T> and(Specification<T> spec) {
            specs.add(spec);
            return this;
        }

        public Builder<T> ifHasText(String str,
                                    Function<String, Specification<T>> specSupplier) {
            if (StringUtils.hasText(str)) {
                specs.add(specSupplier.apply(str));
            }
            return this;
        }

        public Builder<T> ifTrue(Boolean cond,
                                 Supplier<Specification<T>> specSupplier) {
            if (cond != null && cond.booleanValue()) {
                specs.add(specSupplier.get());
            }
            return this;
        }

        public Specification<T> toSpec() {
            Specification<T> spec = Specification.where(null);
            for (Specification<T> s : specs) {
                spec = spec.and(s);
            }
            return spec;
        }
    }
}
```

| 메서드 | 역할 |
|--------|------|
| `builder(Class<T>)` | 빌더 생성 (정적 팩토리) |
| `and(spec)` | 무조건 스펙 추가 |
| `ifHasText(str, fn)` | **문자열에 값이 있으면** 스펙 추가 |
| `ifTrue(cond, supplier)` | **조건이 참이면** 스펙 추가 |
| `toSpec()` | 모아둔 스펙들을 `where(null)`부터 **`and()`로 결합** |

> [!tip] 확장
> `ifTrue()`, `ifHasText()`, `and()` 메서드가 있는데 **이 외에 필요한 메서드를 추가해서 사용하면 된다.**

## Exam/Test Patterns (시험 빈출 패턴)

| Scenario/Keyword | Answer |
|-------------------|--------|
| "조건부 스펙 조합의 문제" | **`if` 블록 + 변수 재할당 반복** |
| "스펙 빌더의 효과" | **가독성 ↑, 구조 단순화** (코드 양은 비슷) |
| "빌더의 세 메서드" | **`and()`, `ifTrue()`, `ifHasText()`** |
| "`toSpec()`의 시작점" | **`Specification.where(null)`** |
| "빌더는 확장 가능한가?" | **필요한 메서드를 추가해서 사용** |
