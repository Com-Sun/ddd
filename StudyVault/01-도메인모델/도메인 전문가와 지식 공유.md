# 도메인 전문가와 개발자 간 지식 공유 (★★)

#ddd #domain-model #concept

## Overview Table (한눈에 비교)

| 항목 | 핵심 내용 |
|------|-----------|
| 요구사항의 위상 | **첫 단추** — 잘못 끼우면 모든 것이 어긋난다 |
| 가장 간단한 해법 | 개발자와 도메인 전문가가 **직접 대화**한다 |
| 전달자가 많을수록 | 정보가 **왜곡·손실**되어 엉뚱한 것을 만들게 된다 |
| GIGO | Garbage In, Garbage Out — 잘못된 요구사항 → 잘못된 제품 |
| 주의 | 도메인 전문가의 요구가 **항상 옳은 것은 아니다** |
| 개발자가 할 일 | "왜 이 기능을 원하는가"를 물어 **진짜 원하는 것**을 찾는다 |

## 요구사항은 첫 단추다

> [!important] 코드는 단추가 아니다
> 단추는 풀어서 다시 끼우기 쉽지만, 잘못 개발한 코드를 올바르게 고치려면 **많은 노력이 든다.**
> 요구사항을 잘못 이해하면 다시 만들 코드가 많아지고, 제품 개발에 실패하거나 일정이 크게 밀린다.

## 전달자가 많을수록 정보는 왜곡된다

```
[ 나쁜 구조 ]  전문가 ─▶ 기획자 ─▶ PM ─▶ 리더 ─▶ 개발자
                       └── 단계마다 왜곡·손실 누적 ──┘
                              결과: 최초 요구와 다른 무언가

[ 좋은 구조 ]  전문가 ◀────── 직접 대화 ──────▶ 개발자
                              결과: 왜곡 최소화
```

- 개발자와 전문가 사이에 내용을 전파하는 **전달자가 많을수록** 정보가 왜곡되고 손실이 발생한다.
- 도메인 전문가만큼은 아니더라도 **이해관계자와 개발자도 도메인 지식을 갖춰야** 한다.
- 전문가·관계자·개발자가 **같은 지식을 공유하고 직접 소통할수록** 원하는 제품이 나올 가능성이 높아진다.

## GIGO — Garbage In, Garbage Out

> [!warning] 잘못된 요구사항이 들어가면 잘못된 제품이 나온다
> 소프트웨어 분야의 유명한 문장 "Garbage In, Garbage Out"은 **요구사항에도 그대로 적용**된다.

## 전문가의 요구가 항상 옳은 것은 아니다

도메인 전문가는 **소프트웨어 전문가가 아니기 때문에**, 기존에 만들어진 소프트웨어를 기준으로 요구사항을 맞출 때가 있다.

**책의 설문 조사 사례 (p.026)**

| 단계 | 내용 |
|------|------|
| 표면적 요구 | "목록의 **전체 설문을 한번에 선택해서 반려**하는 기능을 달라" |
| 대화로 밝혀진 의도 | 설문을 다 볼 시간이 없다. 등록 후 **1주일이 지난 미승인 설문은 반려** 처리하는데, 건수가 늘어 시간이 오래 걸린다 |
| 개발자의 역제안 | "1주일 지난 미승인 설문을 **자동으로 반려 처리**하면 될까요?" |
| 결과 | "그렇게 해 주시면 좋죠! 일도 편해지겠네요." — **더 나은 해법** |

> [!tip] 요구사항을 들을 때 반드시 묻는 두 가지
> 1. **왜** 이런 기능을 요구하는가?
> 2. 실제로 원하는 것(진짜 문제)은 무엇인가?

전문가나 관련자가 요구한 내용이 항상 올바른 것은 아니며, 때론 **본인들이 실제로 원하는 것을 정확하게 표현하지 못할 때도 있다.**

> [!note] 도메인 전문가의 정의
> "도메인 전문가가 전문가로 있는 영역"을 도메인이라고 정의한 책도 있을 만큼, DDD에서 도메인 전문가의 비중은 크다.

## Exam/Test Patterns (시험 빈출 패턴)

| Scenario/Keyword | Answer |
|-------------------|--------|
| "요구사항 왜곡을 줄이는 가장 간단한 방법" | 개발자와 도메인 전문가의 **직접 대화** |
| "Garbage In, Garbage Out" | 잘못된 **요구사항** → 잘못된 제품 |
| "전문가가 요구한 기능을 그대로 만들면 된다?" | **거짓.** 의도를 파악해 더 나은 해법을 제안해야 함 |
| "전달자가 많으면?" | 정보 **왜곡·손실** 증가 |
| "개발자도 도메인 지식이 필요한가?" | **필요하다.** 이해관계자·개발자 모두 |
