| 항목 | 핵심 내용 |
|------|-----------|
| 정의 | **관련 객체를 하나로 묶은 군집** |
| 등장 배경 | 도메인 모델이 복잡해지면 **상위 수준에서 모델을 관리할 수 없게 된다** |
| 효과 | 개별 객체가 아닌 **애그리거트 간의 관계**로 도메인 모델을 이해·구현 |

## 왜 애그리거트가 필요한가

> [!warning] 복잡해지면 큰 그림을 잃는다
> 도메인 모델이 복잡해지면 개발자가 **전체 구조가 아닌 한 개 엔티티와 밸류에만 집중**하는 상황이 발생한다.
> 상위 수준에서 모델을 관리하지 않고 개별 요소에만 초점을 맞추다 보면,
> **큰 수준에서 모델을 이해하지 못해 큰 틀에서 모델을 관리할 수 없는 상황**에 빠질 수 있다.

**지도 비유 (p.084)**

| 지도 | 도메인 모델 |
|------|-------------|
| **대축척 지도**(매우 상세) | 개별 엔티티·밸류 — 어디에 위치하는지 알기 어렵다 |
| **소축척 지도**(큰 수준) | **애그리거트** — 현재 위치를 정확히 이해하게 해준다 |

> [!tip]
> 도메인 모델도 개별 객체뿐 아니라 **상위 수준에서 모델을 볼 수 있어야** 전체 모델의 관계와 개별 모델을 이해하는 데 도움이 된다.
> 이때 도움이 되는 것이 바로 **애그리거트**다.

## 애그리거트 = 관련 객체를 하나로 묶은 군집

대표적인 예가 **주문**이다. '주문'이라는 도메인 개념은 다음 하위 모델로 구성된다.

```
                    [ 주문 애그리거트 ]
   ┌──────────────────────────────────────────────┐
   │   주문(Order)  ◀── 애그리거트 루트            │
   │     ├ 주문자(Orderer)          — 밸류         │
   │     ├ 주문 목록(OrderLine)     — 밸류         │
   │     ├ 배송지 정보(ShippingInfo)— 밸류         │
   │     └ 총 결제 금액(Money)      — 밸류         │
   └──────────────────────────────────────────────┘
        하위 개념을 묶어 '주문'이라는 상위 개념으로 표현
```

> [!important] 효과
> 애그리거트를 사용하면 개별 객체가 아닌 **관련 객체를 묶어서 객체 군집 단위로 모델을 바라볼 수 있다.**
> 개별 객체 간의 관계가 아닌 **애그리거트 간의 관계**로 도메인 모델을 이해하고 구현하게 되며,
> 이를 통해 **큰 틀에서 도메인 모델을 관리**할 수 있다.

## 애그리거트 루트를 통한 접근

> [!danger] 접근 규칙
> 애그리거트를 사용하는 코드는 **애그리거트 루트가 제공하는 기능을 실행**하고,
> 애그리거트 루트를 통해서 **간접적으로** 애그리거트 내의 다른 엔티티나 밸류 객체에 접근한다.
> → 애그리거트의 **내부 구현을 숨겨서 애그리거트 단위로 구현을 캡슐화**할 수 있다.

```java
public class Order {

    public void changeShippingInfo(ShippingInfo newInfo) {
        checkShippingInfoChangeable();   // ★ 배송지 변경 가능 여부 확인
        this.shippingInfo = newInfo;
    }

    private void checkShippingInfoChangeable() {
        // ... 배송지 정보를 변경할 수 있는지 여부를 확인하는 도메인 규칙 구현
        // 예: 이미 배송이 시작된 경우 익셉션을 발생
    }
}
```

> [!important] 왜 루트를 강제하는가
> 주문 애그리거트는 **`Order`를 통하지 않고 `ShippingInfo`를 변경할 수 있는 방법을 제공하지 않는다.**
> 즉 배송지를 변경하려면 **루트 엔티티인 `Order`를 사용해야 하므로**,
> 배송지 정보를 변경할 때에는 **`Order`가 구현한 도메인 로직을 항상 따르게 된다.**

```
   ❌ shippingInfo.setAddress(...)      ← 루트를 우회 → 규칙 검사 누락
   ⭕ order.changeShippingInfo(...)     ← 루트 경유 → 규칙이 항상 적용됨
```

## 구현 시 고려할 점

> [!warning] 애그리거트 구현은 단순하지 않다
> - 애그리거트를 **어떻게 구성했느냐에 따라 구현이 복잡해지기도** 한다.
> - **트랜잭션 범위가 달라지기도** 한다.
> - 선택한 **구현 기술에 따라 애그리거트 구현에 제약**이 생기기도 한다.
>
> → 자세한 내용은 3장 [[애그리거트]] 이후 참고.
