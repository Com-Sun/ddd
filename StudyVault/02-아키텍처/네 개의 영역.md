# 네 개의 영역 (★★★)

#ddd #architecture #concept

## Overview Table (한눈에 비교)

| 영역 | 책임 | 하지 말아야 할 것 |
|------|------|-------------------|
| **표현(Presentation/UI)** | 사용자 요청 해석 → 응용 서비스에 전달, 실행 결과를 사용자가 이해할 형식으로 변환 | 도메인 로직 |
| **응용(Application)** | 사용자에게 제공할 **기능 구현**, 트랜잭션 관리 | **로직을 직접 수행하지 않는다** — 도메인 모델에 위임 |
| **도메인(Domain)** | 도메인의 **핵심 로직 구현** | 구현 기술 의존 |
| **인프라스트럭처(Infrastructure)** | 구현 기술 처리 (RDBMS, 메시징, 외부 API 등) | 논리적 개념 표현 |

## 표현 영역

```
[웹 브라우저]  ──HTTP 요청──▶  [컨트롤러]  ──객체 변환/전달──▶  [응용 서비스]
      ▲                            │                                │
      └────HTTP 응답(JSON 등)──────┴────────메서드 리턴─────────────┘
```

- 웹 애플리케이션의 표현 영역은 **HTTP 요청을 응용 영역이 필요로 하는 형식으로 변환**해서 응용 영역에 전달하고, 응용 영역의 응답을 **HTTP 응답으로 변환**하여 전송한다.
- 웹 브라우저가 HTTP 요청 파라미터로 전송한 데이터 → **응용 서비스가 요구하는 객체 타입**으로 변환
- 응용 서비스가 리턴한 결과 → **JSON 형식**으로 변환해서 HTTP 응답으로 전송

> [!note] "사용자"의 범위
> 여기서 사용자는 소프트웨어를 사용하는 **사람뿐만 아니라 외부 시스템**일 수도 있다.

## 응용 영역

응용 영역은 시스템이 사용자에게 제공해야 할 **기능**을 구현한다. (주문 등록, 주문 취소, 상품 상세 조회 등)

```java
public class CancelOrderService {

    @Transactional
    public void cancelOrder(String orderId) {
        Order order = findOrderById(orderId);
        if (order == null) throw new OrderNotFoundException(orderId);
        order.cancel();          // ★ 도메인 모델에 위임
    }
}
```

> [!important] 응용 서비스의 핵심 원칙
> 응용 서비스는 **로직을 직접 수행하기보다는 도메인 모델에 로직 수행을 위임한다.**
> 위 코드도 주문 취소 로직을 직접 구현하지 않고 `Order` 객체에 취소 처리를 위임하고 있다.

```
   [ 응용 ]                        [ 도메인 ]
   ┌──────────────┐  기능 실행 위임  ┌──────────────┐
   │ 응용 서비스  │ ──────────────▶ │ 엔티티/밸류  │
   │ (기능 구현)  │                 │ (로직 구현)  │
   └──────────────┘                 └──────────────┘
```

## 도메인 영역

- 도메인 모델을 구현한다. 1장에서 본 `Order`, `OrderLine`, `ShippingInfo` 같은 도메인 모델이 이 영역에 위치한다.
- 도메인 모델은 **도메인의 핵심 로직을 구현**한다.
- 예: 주문 도메인의 **'배송지 변경', '결제 완료', '주문 총액 계산'** 같은 핵심 로직

## 인프라스트럭처 영역

> [!tip] 이 영역은 **논리적인 개념을 표현하기보다 실제 구현을 다룬다.**

| 처리 대상 | 예 |
|-----------|-----|
| RDBMS 연동 | MySQL, 오라클 등 |
| 메시징 | 메시징 큐에 메시지 전송/수신 (Kafka, RabbitMQ 등) |
| NoSQL | 몽고DB(MongoDB), 레디스(Redis) 데이터 연동 |
| 메일 | SMTP를 이용한 메일 발송 |
| 외부 API | HTTP 클라이언트를 이용한 REST API 호출 |

> [!important] 다른 영역과의 관계
> 도메인 영역, 응용 영역, 표현 영역은 **구현 기술을 사용한 코드를 직접 만들지 않는다.**
> 대신 **인프라스트럭처 영역에서 제공하는 기능을 사용**해서 필요한 기능을 개발한다.
> (예: 응용 영역에서 DB에 보관된 데이터가 필요하면 인프라스트럭처 영역의 DB 모듈을 사용한다.)

## Exam/Test Patterns (시험 빈출 패턴)

| Scenario/Keyword | Answer |
|-------------------|--------|
| "HTTP 요청 파라미터를 객체로 변환" | **표현 영역** |
| "결과를 JSON으로 변환해 응답" | **표현 영역** |
| "사용자에는 외부 시스템도 포함" | **표현 영역** |
| "주문 등록·취소 기능 구현" | **응용 영역** |
| "로직을 직접 수행하지 않고 위임" | **응용 영역** → 도메인 모델 |
| "배송지 변경·결제 완료·총액 계산" | **도메인 영역** |
| "MongoDB/Redis/SMTP/REST 호출" | **인프라스트럭처 영역** |
| "논리적 개념보다 실제 구현을 다룸" | **인프라스트럭처 영역** |
